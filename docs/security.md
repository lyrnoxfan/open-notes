# 安全存储说明

## 为什么用包裹而不是派生

由设备标识派生的口令是可复现的：能读到那些标识的一方就能重新派生出密钥，加密也就失去意义。
这里的口令是 `SecureRandom` 生成的 32 字节，只能通过 Android Keystore 中的不可导出密钥取得。

## 各道防护对应的失败

| 防护 | 阻止的失败 |
| --- | --- |
| `DatabaseFileGuard.requireNoPlaintextDatabase` | 旧版本或错误构建写出过明文库；静默采用它等于以明文读取笔记 |
| `DatabaseFileGuard.requireEncryptedDatabase` | Room 构建器漏挂 SQLCipher factory 时悄悄退化成明文 |
| `DatabaseKeyManager` 往返校验 | 用一个从未持久化的口令建库，得到一个永远打不开的数据库 |
| `WrappedSecret` 版本字节 | 将来更换封装格式时把旧密文当成新格式解析 |
| `EncryptedDatabaseProvider` 的密钥缺失分支 | 密钥丢失时默默新建密钥、重建空库，用户数据看似「消失」 |
| 备份排除规则 | 密文与包裹密钥一起被带离设备 |
| 应用锁（`AppLockManager`） | 设备已解锁时，他人直接打开应用读到明文笔记 |
| 锁定时不组合笔记界面（`AppLockGate`） | 「先显示再遮挡」的中间帧把正文泄露一瞬 |
| 锁定时关闭数据库连接（`AppContainer.closeDatabase`） | 锁定后进程里仍留着一个可查询的连接 |
| 30 秒宽限与系统界面豁免 | 指纹弹窗、设备凭据页、文件选择器往返被误判成离开应用，反复要求认证 |
| `FLAG_SECURE`（`SecureWindow`） | 截图、录屏与最近任务预览里出现笔记内容 |

## 已知限制：密钥失效

Keystore 条目被销毁后包裹口令不可恢复，现有数据库无法打开。当前行为是抛出
`DatabaseKeyException.KeyUnavailable`，界面显示错误并提示通过备份恢复，不自动重建空库、不删除
原文件。完整的恢复/导出流程属于阶段五（备份与恢复）。

## 日志

应用不写任何日志，没有 `android.util.Log` 调用。异常信息里不含口令、标题或正文：密钥相关异常只
说明 Keystore 别名缺失或认证失败，不含密钥内容。

## 应用锁保护的范围

应用锁挡的是「拿到已解锁手机的人」：进入应用、从后台切回、看最近任务预览。它不承诺对抗已经取得
设备控制权的一方——Root、调试进程、注入或读内存都可以绕过任何应用内的界面锁，方案 §6.2 对此有明确
说明。数据库加密（静态数据）与应用锁（使用路径）是两道不同的防线，互不替代。

具体行为：

- 关闭应用锁时，应用不做认证；开启后立即生效，但不会把正在使用的用户当场锁在外面。
- 只有认证成功才解除锁定；取消、失败、系统锁定都保持锁定状态。
- 设备没有设置锁屏密码/图案/PIN 时，应用锁拒绝开启，并引导去系统安全设置。否则会出现「锁得上、
  解不开」的状态，用户会被自己的笔记挡在门外。
- 离开应用超过 30 秒才需要重新认证；小于等于 30 秒返回不打扰。
- 指纹提示、设备凭据页与后续的文件选择器都走 `beginSystemUi`／`endSystemUi` 豁免，不会因为它们
  把应用推到后台而触发锁定。若系统界面没有回调，下一次回到前台会清掉豁免标记，不会永久失效。

## 截图防护

`FLAG_SECURE` 无条件设置在窗口上，不跟随应用锁开关：列表、编辑、回收站、锁屏任何一屏都可能包含私人
内容，没有哪一屏适合放开截图。代价是用户无法对笔记截图，这是刻意的取舍。
