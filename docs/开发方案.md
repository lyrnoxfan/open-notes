私密笔记 App 开发方案

1. 项目目标

开发一款原生 Android 私密笔记应用，作为个人日常记录和博客发布前的私人草稿箱。

博客与 App 完全独立，不共享数据库、账号、接口或内容。App 以本地离线使用为主，WebDAV 仅用于备份，不作为笔记在线服务。

核心优先级

1. 美观：暖纸色视觉风格，界面精致、留白充足、排版舒适。
2. 数据可靠：自动保存、加密存储、回收站、可靠备份和恢复。
3. 隐私：数据库加密、应用锁、防截图，尽可能减少明文数据暴露。
4. 体验：操作简单、响应流畅、离线可用，不堆砌功能。

v1 功能范围

- 笔记列表、新建、编辑、自动保存、删除与恢复。
- Markdown 编辑与实时预览。
- 标签创建、管理、筛选。
- 标题和正文全文搜索。
- 回收站，删除 30 天后自动清理。
- 加密数据库、指纹锁、系统凭据兜底。
- JSON 导入与导出，支持可选密码加密。
- SAF 本地备份、WebDAV 自动备份。
- 备份状态、应用锁设置、关于页面。
- GitHub Actions 自动构建签名 Release APK。

桌面小组件、分享、图片附件及跨设备实时同步不属于 v1。

2. 技术选型

项目| 方案
开发语言| Kotlin
UI| Jetpack Compose + Material 3
数据库| Room + SQLCipher
密钥管理| Android Keystore
应用锁| AndroidX Biometric / BiometricPrompt
Markdown| CommonMark + Markwon
自动备份调度| WorkManager
本地文件访问| Storage Access Framework（SAF）
网络备份| HTTPS WebDAV
JSON| Kotlin Serialization
依赖管理| Gradle Version Catalog
CI/CD| GitHub Actions
发布格式| 签名 APK

采用单个 Android 应用模块，按功能划分 package，不为小项目引入不必要的多模块架构。

技术选型要求：

- 使用当前受支持的 "sqlcipher-android"，不要引入旧的、已弃用的 "android-database-sqlcipher"。
- Room 与 SQLCipher 使用经过验证的兼容版本组合。
- 数据库必须从第一次创建起就使用加密存储。
- 不使用 WebView，不把网页套壳作为 App。
- 不引入账号系统、分析 SDK、广告 SDK 或无必要的第三方服务。
- 依赖版本统一管理，禁止随意升级导致数据库或构建兼容性问题。

4. UI 与视觉规范

4.1 设计基调

以博客的暖纸系配色为基础，整体采用温暖、克制、精致的编辑器风格。

设计用途| 颜色
浅色主背景| "#F1E7DA"
主强调色| "#A13F04"
正文| 深暖棕色
次要文字| 灰棕色
分割线与边框| 低对比度暖灰色
深色背景| 深暖棕，不使用纯黑
深色主强调色| 与暖纸色背景保持足够对比的暖橙棕

具体颜色集中定义为 Design Tokens，不在页面中散落硬编码颜色。

4.2 视觉要求

- 留白充足，避免内容拥挤。
- 圆角统一，卡片与按钮保持一致的设计语言。
- 不使用大面积模糊、玻璃拟态或过度阴影。
- 不做传统后台管理系统式布局。
- 列表简洁清晰，标题、正文摘要、标签和更新时间层级分明。
- 编辑页面优先保证文字阅读和输入体验。
- 图标统一，动画轻量，不影响低端设备流畅度。
- 支持浅色和深色模式，深色模式同样使用暖棕配色。
- 中文字体优先采用系统字体；需要衬线风格时优先测试系统衬线字体。只有确实有必要时才打包裁剪后的 Noto Serif SC。

4.3 页面布局

笔记列表

顶部为页面标题与搜索入口，正文区域展示笔记条目，包含标题、简短摘要、更新时间和标签。提供新建入口及标签筛选。

笔记编辑页

顶部为返回、保存状态和更多操作；中间为标题与编辑区；底部或菜单中提供预览切换和标签管理。保存状态应真实反映数据库写入结果。

回收站

展示删除时间与剩余保留时间，支持恢复与永久删除。

设置页

分区展示应用锁、本地备份、WebDAV、导入导出、备份状态和关于信息。重要操作需要明确提示。

5. 数据模型

5.1 Note

字段| 类型| 说明
id| UUID / String| 全局唯一标识
title| String| 标题
content| String| Markdown 原文
createdAt| Long| 创建时间
updatedAt| Long| 最后修改时间
deletedAt| Long?| 删除时间，未删除为 null

时间统一使用 UTC Unix 时间戳，UI 按设备时区显示。

5.2 Tag

字段| 类型| 说明
id| UUID / String| 标签唯一标识
name| String| 标签名称
createdAt| Long| 创建时间
updatedAt| Long| 修改时间

另建 "NoteTagCrossRef" 关联笔记与标签，使用稳定 ID，而不是仅依赖标签名称关联。

5.3 删除记录

建立轻量级删除标记表，记录已永久删除的笔记 ID、删除时间和相关版本信息，避免导入旧备份时意外复活已经删除的笔记。

删除超过 30 天的笔记清除正文，但保留必要的删除标记。删除标记的清理策略必须兼顾旧备份导入时的冲突问题。

5.4 数据库规则

- 使用事务完成涉及多张表的操作。
- 时间戳更新必须集中处理。
- 数据库迁移必须逐版本实现并测试。
- 禁止使用 destructive migration 或任何自动清空数据库的升级回退方案。
- 备份格式版本与数据库 schema 版本分别管理，不能混为一谈。

6. 数据安全设计

6.1 SQLCipher 数据库加密

首次启动时生成随机数据库密钥，通过 Android Keystore 中的密钥进行加密封装。数据库启动时解封装数据库密钥，再交给 SQLCipher 使用。

不得把数据库原始密钥以明文保存在普通 SharedPreferences、源码、日志或固定配置中。

要求：

- 数据库正文、标题、标签、回收站内容均受到数据库加密保护。
- 数据库首次创建就启用加密，不允许先写明文、之后再考虑加密。
- 正确密钥才能打开数据库，密钥错误时必须安全报错。
- 不把数据库密钥、笔记正文或 WebDAV 凭据写进日志。
- 数据库密钥不可用时，不自动重建空数据库，不删除原数据库。
- 明确提示用户通过备份恢复，并尽可能保留原始数据供排查。

6.2 应用锁

使用 BiometricPrompt，支持指纹或设备系统凭据验证。

- 用户可开启或关闭应用锁。
- App 进入后台后超过 30 秒，再次进入需要认证。
- 小于或等于 30 秒返回时，不重复要求认证。
- 文件选择器、系统授权界面等正常跳转不应导致无意义的重复锁定。
- 验证成功前，不展示笔记正文。
- 锁定时尽可能清除页面中的敏感内容，并关闭不再需要的数据库连接。
- 认证取消或失败时保持锁定。
- 指纹不可用时允许使用设备 PIN、图案或密码；若设备没有安全凭据，应提示用户先设置。

使用 "FLAG_SECURE" 保护包含敏感信息的窗口，减少截图和最近任务预览泄露。

需要注意：数据库加密主要保护静态数据；应用锁主要保护正常应用使用路径。对于已经取得设备控制权、Root 权限或能够调试应用进程的攻击者，不能承诺绝对安全。

6.3 备份加密

备份密码只用于备份文件加密，不等于数据库密钥。

启用密码保护时：

1. 生成随机 salt 和 AES-GCM nonce。
2. 使用带 salt 的密码派生算法生成加密密钥。
3. 对完整备份内容进行 AES-GCM 加密及完整性验证。
4. 将格式版本、KDF 参数、salt、nonce 等必要元数据保存在文件头。
5. 不保存备份密码，不在日志中输出密码。
6. 错误密码、文件损坏或认证失败时拒绝导入，不能产生半成功的恢复结果。

关闭密码保护时，备份为明文 JSON，并在导出前明确提示：文件包含完整的私人笔记，任何能够读取文件的人都可以查看。

7. 自动保存与编辑器

7.1 自动保存流程

用户编辑内容后，使用 1 秒防抖机制保存，减少频繁写入。同时在页面退出、应用进入后台等适当时机触发最终保存。

流程：

1. 用户输入。
2. 更新页面内的编辑状态。
3. 每次输入重置防抖计时。
4. 停止输入约 1 秒后，将最新标题和正文写入数据库。
5. 数据库事务成功后更新保存状态。
6. 写入失败时显示明确错误，不伪装成已保存。
7. 下次进入编辑器时从数据库读取最新已持久化版本。

保存操作需要处理快速切页、连续编辑、并发写入和页面销毁。较早的保存任务不能覆盖较新的内容。

如果发生进程被系统强制终止，最多可能丢失尚未完成持久化的输入；因此应尽可能缩短未保存窗口，并测试后台与异常终止场景。

7.2 Markdown

编辑器保存 Markdown 原始文本，预览由渲染器完成。

- 不把预览后的 HTML 当作原文保存。
- 博客的换行规则必须一致：普通文本中的单个换行也显示为换行，而不是合并成空格。
- 不依赖默认渲染行为碰运气，需通过自定义软换行处理实现。
- 编辑与预览切换时必须保留光标、滚动位置及未提交输入。
- 标题、列表、引用、代码块、链接和分隔线等常用 Markdown 语法需要支持。
- 仅支持必要的 Markdown 能力，不引入完整的网页渲染环境。

7.3 全文搜索

v1 使用参数化 SQL 查询，对标题和正文进行包含式匹配，搜索范围默认排除已删除笔记。

- 几千条笔记内优先选择实现简单、行为可预测的方案。
- 对 SQL 特殊字符正确处理。
- 不拼接用户输入生成原始 SQL。
- 搜索结果显示标题、摘要、标签及更新时间。
- 标签筛选与关键词搜索可以组合使用。

不在 v1 引入复杂中文分词，后续根据实际性能和体验再评估。

8. 回收站

删除笔记时不立即物理删除，而是设置 "deletedAt"。

- 默认列表不展示回收站内容。
- 回收站展示删除时间及剩余天数。
- 支持恢复，恢复后重新出现在正常列表中。
- 支持手动永久删除，执行前二次确认。
- 超过 30 天后自动清理正文及不再需要的关联数据。
- 永久删除产生的删除标记应保留足够久，以免较旧的备份重新导入后复活已删除内容。
- 回收站清理必须使用事务，不能出现正文消失但关联数据残留的异常状态。

9. 备份与恢复

这是本项目的关键模块，必须先保证恢复可靠，再开发自动化调度。

9.1 统一备份格式

建议结构如下：

{
  "format": "private-notes-backup",
  "schemaVersion": 1,
  "appVersion": "1.0.0",
  "exportedAt": 0,
  "notes": [],
  "tags": [],
  "noteTags": [],
  "deletionMarkers": []
}

时间字段使用 UTC 时间戳。格式升级必须考虑旧版兼容，导入器需要检查版本、必需字段、字段类型和数据完整性。

加密备份使用独立的外层封装格式，不能把明文 JSON 当成加密文件处理。

9.2 本地备份

用户首次进入备份设置时，通过 SAF 选择目录，例如 "Documents/笔记备份"。

- 使用持久化 URI 授权，避免每次备份重复选择目录。
- 在用户选择的目录创建带时间戳的备份文件。
- 每天自动生成一份完整备份。
- 保留历史文件，不能直接覆盖唯一的最新备份。
- 写入完成后检查文件可读性及内容完整性。
- 备份失败时保留之前的有效备份，并显示失败状态。
- 提供手动立即备份功能。
- 如果目录权限失效或目录被移除，提示用户重新授权。

自动本地备份不应该依赖用户打开文件选择器才能执行。

9.3 WebDAV 备份

用户自行配置 HTTPS WebDAV 地址、用户名、密码和远端目录。

- 密码等凭据使用 Keystore 保护的方式保存。
- 只允许正常的 HTTPS 连接，不关闭证书校验。
- 每天生成一份完整备份并上传，使用唯一文件名。
- 上传结束后尽可能验证远端文件是否完整可读。
- 网络中断时保留本地备份，并重试远端任务。
- 未配置 WebDAV 时，不能影响笔记编辑和本地备份。
- 分开记录本地备份状态与远端备份状态。
- 提供手动测试连接、立即备份和失败重试。

WebDAV 仅承担单向备份，不实现自动双向同步，也不允许远端文件未经确认直接覆盖本地数据。

9.4 自动调度

使用 WorkManager 调度周期性任务，并在 App 启动、恢复前台以及适当的退出路径检查是否超过一天未备份。

如果超过一天：

1. 立即触发或安排一次补备份。
2. 本地备份与 WebDAV 备份分别执行，避免其中一项失败导致另一项失败。
3. 无网络时完成本地备份，并将远端任务安排重试。
4. 更新各自最后成功时间。
5. 失败后保留错误原因及下次重试条件。

Android 的后台任务会受到电池优化和系统调度影响，因此不能承诺每天固定时刻执行，也不能依赖应用退出回调保证任务完成。必须结合 WorkManager 持续重试与前台补检，尽可能保证最终执行。

9.5 导入与合并

默认导入方式为合并，不直接覆盖现有数据库。

对于相同 UUID 的笔记：

- 备份中的 "updatedAt" 更新：采用备份版本。
- 本地 "updatedAt" 更新：保留本地版本。
- UUID 不存在：新增笔记。
- 相同时间戳但内容不同：保留本地内容并记录冲突，不能静默丢弃其中一份。
- 删除标记参与合并，避免旧版本复活已删除笔记。
- 标签按稳定 ID 合并，并检查关联关系完整性。

导入流程：

1. 读取文件。
2. 必要时要求输入备份密码。
3. 完整解密并校验文件。
4. 检查格式与 schema 版本。
5. 解析全部数据并验证关联。
6. 在事务中执行合并。
7. 事务成功后更新界面。
8. 失败时回滚所有更改，原数据保持不变。

大型导入之前，应先创建当前数据库的安全备份。

如需提供完全替换式恢复，必须将其作为独立且明确的高风险操作，先备份现有数据，并进行二次确认。

9.6 备份状态页

至少展示：

- 本地备份目录。
- 最近一次本地备份成功时间。
- 最近一次 WebDAV 备份成功时间。
- 当前任务状态。
- 最近一次失败原因。
- 立即备份、重新授权和重试入口。

仅在备份写入及必要的完整性验证成功后更新最后成功时间，不能在任务刚开始时就标记成功。

10. GitHub Actions 与 Release

仓库设置为私有仓库，GitHub Actions 完成构建、测试与发布。

工作流程

提交代码或创建 Pull Request：

- Gradle 编译。
- 单元测试。
- 静态检查与 Lint。
- 生成测试构建，发现构建回归。

推送版本标签，例如 "v1.0.0"：

- 执行正式版编译。
- 启用 R8 混淆与代码优化。
- 使用固定的发布密钥进行签名。
- 验证 APK 签名。
- 将 APK 发布至对应 GitHub Release。

签名要求

- 不把 keystore 文件、密码或私钥提交至仓库。
- 使用 GitHub Secrets 提供构建所需的签名材料。
- 保留离线的 keystore 安全备份。
- 包名、签名证书及更新签名保持一致，确保后续 APK 能覆盖安装。
- 每次发布递增 "versionCode"，版本号与 Git 标签保持一致。

正式签名配置必须在首次发布前完成验证。不能仅仅确认构建成功，却没有测试新版本能否覆盖安装旧版本。

11. 开发顺序与阶段交付

阶段一：工程基础与安全存储

完成项目初始化、依赖管理、主题框架、Room 数据模型、SQLCipher 加密和密钥管理。

交付标准：

- 可以稳定编译和安装。
- 数据库首次创建即加密。
- 数据库重新打开后数据保持完整。
- 不允许因密钥错误而清空数据。

阶段二：笔记基本功能

完成列表、新建、编辑、自动保存、删除、回收站和恢复。

交付标准：

- 常规编辑无需手动保存。
- 连续快速编辑时不会被旧保存任务覆盖。
- 删除和恢复符合预期。
- 杀进程重新打开后，已持久化数据仍存在。

阶段三：Markdown、标签与搜索

完成渲染器、单换行规则、标签 CRUD、筛选和包含式搜索。

交付标准：

- 换行与博客规则一致。
- Markdown 切换不丢内容。
- 搜索和标签筛选结果正确。
- 搜索不因特殊 SQL 字符导致异常。

阶段四：应用锁与隐私

完成生物识别、设备凭据兜底、30 秒后台宽限、截图防护和锁定界面。

交付标准：

- 认证失败不能进入笔记页面。
- 超时返回必须重新认证。
- 系统文件选择器往返体验正常。
- 最近任务预览和截图受到保护。

阶段五：备份文件与恢复

先完成 JSON 格式、本地 SAF 导出、加密备份、导入校验和合并逻辑，再开发 WebDAV。

交付标准：

- 明文和密码加密备份都能正常导出、导入。
- 错误密码和损坏文件会被拒绝。
- 合并冲突按照规定处理。
- 导入失败完全回滚。
- 旧备份不会静默覆盖新数据。

阶段六：WebDAV 与自动备份

完成设置页、连接测试、后台任务、重试、状态显示与前台补检。

交付标准：

- 网络中断不影响本地备份。
- WebDAV 失败后可重试。
- 不误报备份成功。
- 后台任务受限时，App 再次启动能够检查并补备份。

阶段七：发布与验收

完成正式签名、R8、Release 工作流和覆盖安装测试。

交付标准：

- GitHub Actions 可独立构建正式 APK。
- APK 签名有效。
- 同签名新版本能够覆盖安装。
- 数据库升级不会丢失已有笔记。
- 干净安装、升级安装及备份恢复均通过测试。

12. 最低测试清单

以下测试必须实际执行，而不能仅凭代码审查认定通过。

数据可靠性

- 新建笔记后立即退出。
- 连续输入并快速切换页面。
- 输入后立即杀死进程。
- 升级前后检查原有笔记、标签和回收站。
- 模拟数据库迁移失败，确认不会静默清空数据。

隐私

- 检查数据库文件不是可直接读取的明文 SQLite 内容。
- 使用错误密钥尝试打开数据库。
- 截图及最近任务预览检查。
- 验证锁定超时及认证失败行为。
- 检查日志中不存在标题、正文、密码及密钥。

备份恢复

- 明文备份完整往返。
- 加密备份正确密码往返。
- 错误密码与损坏文件导入。
- 相同 UUID 的新旧数据合并。
- 删除标记与旧备份冲突。
- SAF 目录授权失效。
- WebDAV 断网、中途失败、服务器不可用。
- 多份历史备份中恢复指定版本。
- 确认任何失败都不会覆盖唯一有效备份。

发布

- 正式构建和签名验证。
- 新旧版本覆盖安装。
- Release APK 在目标 Android 设备上真实运行。
- 验证正式版仍然包含 SQLCipher 所需的原生库。
- 验证 R8 开启后加密、数据库迁移和备份功能正常。

13. 最终验收原则

项目必须同时满足以下条件才算 v1 完成：

1. 视觉达到暖纸系、留白充足、精致耐看的要求。
2. 所有笔记操作真实写入本地数据库。
3. 自动保存、回收站和数据库迁移正常。
4. 数据库加密及应用锁有效。
5. 本地备份与 WebDAV 备份状态可验证。
6. 导出、导入、加密和恢复均经过真实测试。
7. GitHub Actions 能构建可覆盖安装的正式 APK。
8. 没有为了快速交付而留下假的保存按钮、前端缓存式已读/保存状态或空实现。
9. 不得用删除数据库、重建数据库或静默丢弃冲突的方式规避错误。
10. 每一阶段交付前先运行测试，修复问题后再进入下一阶段。

14. 开发约束

- 优先采用简单、直接且容易维护的实现。
- 不做需求之外的功能，不为了抽象而抽象。
- 不用模拟数据冒充真实功能。
- 不隐藏失败，不吞掉关键异常。
- 遇到兼容性问题，应定位具体原因并修复，而不是不断叠加补丁。
- 修改已有实现前先检查其真实调用链和数据流。
- 完成后提供实际修改文件、构建结果、测试结果和已知限制。
- 未实际运行的测试不得声称已经通过。
- 所有未完成项目明确标记，不得将占位实现当成完成品。
